# Program Rename Plan: Energy Savings Program, HESP, ESP

## Scope and Evidence

Snapshot date: 2026-11-10. Source: the current working tree of bc-emli-application-sys, including tracked files and non-ignored untracked files. No application source, translations, assets, infrastructure, or runtime data were changed by this assessment. Replacement names have not been provided; use approved replacements rather than guessed branding.

The text scan is case-insensitive for names and includes joined, hyphenated, underscore, and URL-encoded spellings. Acronym matching includes standalone/underscore forms and leading camel-case identifiers (for example esp_application, espApplication, and HespApplicationSys), but excludes incidental substrings such as response. Each inventory row represents one matching source line, even when that line contains several matches. Full source lines are included without truncation; leading indentation is omitted for readability. Line numbers are 1-based and valid at this snapshot; re-scan after implementation because they will move.

Both frontend i18next resources and all three Rails locale files were scanned: app/frontend/i18n/i18n.ts, config/locales/en.yml, config/locales/devise.en.yml, and config/locales/devise_invitable.en.yml. The frontend resource definition is English; no additional language resource files were found in these translation directories. Do not rename translation keys simply because their names contain old branding.

Dependency trees, caches (including .eslintcache), build/runtime directories (vendor, node_modules, log, tmp, storage, .npm, .ruby-lsp), Git history, and ignored local configuration are excluded. package.json and package-lock.json are retained as technical-reference evidence, not display-copy targets. Production database content, CMS content, secrets, externally hosted files, and deployed environment values are not available from this source scan. Check them separately before release.

Raster images cannot supply source line numbers. The current logo.png was visually inspected and contains cleanBC and BETTER HOMES. logo-old.png shows British Columbia only; social-preview.jpg and the three inspected header/background PNGs are scenic imagery, not observed program wordmarks. SVG source was text-scanned, but outlines can encode lettering without searchable text. The complete local image/PDF inventory is included below for further visual review. PDF text extraction and OCR tools were unavailable; no claim of complete visual/OCR clearance is made. Externally linked contractor PDFs were identified through their URLs but were not downloaded or inspected; their content and redirects require owner confirmation.

## Implementation Plan

1. Obtain the approved full program name, short name/acronym, logo policy, contact addresses, effective date, and treatment of historical records. Confirm whether this is a display-only rename or also a domain/integration/resource migration. Phase 2 is independent of the umbrella rename; preserve CleanBC/Better Homes/Better Buildings unless phase 1 is also approved.
2. Update Translations: frontend public/contractor/admin headings, application and invoice wording, resource titles, privacy notice, support and contact values, site titles, and long-form program descriptions; Rails subject prefixes/welcome/invitation/reminder subjects and approval copy. Preserve stable translation keys, interpolation tokens, and markup.
3. Update UI and page metadata plus Maintenance page: hard-coded application/invoice strings, successful-submission defaults, nav alt text, landing/navigation labels, HTML title, Open Graph/Twitter descriptions/titles, and maintenance-page branding. Resolve the approved short/full-name rules consistently across each audience.
4. Update Email and legally approved EULA wording. Review sender display name, subject prefix, signatures, hard-coded links and mailboxes as well as template bodies. Changes to names must not alter prior acceptance/audit records or previously issued immutable documents.
5. Confirm replacements for BetterHomesESP@CLEAResult.com, HESP/ESP-labelled support/integration addresses, energy-savings-program URL paths, esp.clearesult.ca document URLs, hosted forms, and brochures. A label change is not evidence a domain or endpoint changed. Preserve existing URLs until their owner provides replacements/redirects.
6. Keep the Technical and deployment inventory out of an ordinary branding substitution. Examples include HespApplicationSys, EspApplicationController, esp_application routes, frontend API calls, hespColors, hesp-* service/release names, registries, DNS, certificate names, configuration keys, database/bucket identifiers, and automation scripts. These references may remain unchanged indefinitely after a public rename. If technical renaming is explicitly required, scope it as a separate migration with backward-compatible API aliases, dependency/import changes, secret/config updates, resource/data ownership mapping, DNS/TLS/mailbox coordination, rollback, and environment-by-environment rollout. Never blindly replace hesp/esp across Helm or live resources.
7. Review Tests and API documentation: align public Swagger titles/server descriptions and display-copy assertions where appropriate, while preserving existing request paths, fixture IDs, external-system fields, and published integration contracts unless deliberately migrating them. If changing the package name, update package.json and package-lock.json together, not dependency entries unrelated to this program.
8. Review current operational Documentation and named files separately from historical evidence. The ESP-named monitoring investigation and runbooks contain real HESP resource/host names; keep commands accurate until those resources actually change. Check production database-driven requirement/template content, imported descriptions, notifications queued before release, and environment-configured sender/root URLs outside this repository.
9. Execute a copy-only release independently, or attach the explicitly approved technical migration as a separate change window. Document retained names and aliases with owners, reasons, and any expiry dates.
