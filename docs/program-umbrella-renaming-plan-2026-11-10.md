# Program Umbrella Rename Plan: CleanBC, Better Homes, Better Buildings

## Scope and Evidence

Snapshot date: 2026-11-10. Source: the current working tree of bc-emli-application-sys, including tracked files and non-ignored untracked files. No application source, translations, assets, infrastructure, or runtime data were changed by this assessment. Replacement names have not been provided; use approved replacements rather than guessed branding.

The text scan is case-insensitive for names and includes joined, hyphenated, underscore, and URL-encoded spellings. Acronym matching includes standalone/underscore forms and leading camel-case identifiers (for example esp_application, espApplication, and HespApplicationSys), but excludes incidental substrings such as response. Each inventory row represents one matching source line, even when that line contains several matches. Full source lines are included without truncation; leading indentation is omitted for readability. Line numbers are 1-based and valid at this snapshot; re-scan after implementation because they will move.

Both frontend i18next resources and all three Rails locale files were scanned: app/frontend/i18n/i18n.ts, config/locales/en.yml, config/locales/devise.en.yml, and config/locales/devise_invitable.en.yml. The frontend resource definition is English; no additional language resource files were found in these translation directories. Do not rename translation keys simply because their names contain old branding.

Dependency trees, caches (including .eslintcache), build/runtime directories (vendor, node_modules, log, tmp, storage, .npm, .ruby-lsp), Git history, and ignored local configuration are excluded. package.json and package-lock.json are retained as technical-reference evidence, not display-copy targets. Production database content, CMS content, secrets, externally hosted files, and deployed environment values are not available from this source scan. Check them separately before release.

Raster images cannot supply source line numbers. The current logo.png was visually inspected and contains cleanBC and BETTER HOMES. logo-old.png shows British Columbia only; social-preview.jpg and the three inspected header/background PNGs are scenic imagery, not observed program wordmarks. SVG source was text-scanned, but outlines can encode lettering without searchable text. The complete local image/PDF inventory is included below for further visual review. PDF text extraction and OCR tools were unavailable; no claim of complete visual/OCR clearance is made. Externally linked contractor PDFs were identified through their URLs but were not downloaded or inspected; their content and redirects require owner confirmation.

## Implementation Plan

1. Obtain the approved replacement umbrella names, logos/brand guidelines, domains, support mailboxes, and effective date. Treat CleanBC, Better Homes, and Better Buildings as separate mappings; do not assume one replacement applies to all three. Better Buildings is present in energy-coach links to betterbuildingsbc.ca/connect/, not just visible prose.
2. Update the Translations inventory first: frontend onboarding/privacy notice, landing/eligibility copy, application confirmations, administration labels, site/page/navigation titles, support contacts, and resource labels; Rails email subject prefixes, invitation subjects, welcome subjects, invoice reminders, and onboarding approval text. Preserve Energy Savings Program/HESP/ESP when only phase 1 is approved. Keep interpolation tokens and HTML/Trans component structure unchanged.
3. Update hard-coded UI defaults and accessible labels in UI and page metadata, notably successful-submission.tsx and nav-bar.tsx. Updating i18n alone will not cover these. Update support, footer, login, and contractor resource link consumers if their destination values or labels change; stable betterHomes translation keys can remain.
4. Replace public/images/logo.png with the approved umbrella lockup. Review its navigation, shared email, and PDF-cover consumers listed below; adapt dimensions/aspect ratio if the artwork differs and invalidate cached assets. Review SVG/legacy/social/favicon variants for consistency, but do not replace unrelated provincial or Building Permit Hub assets without confirming their ownership and use.
5. Update shared email-layout branding/alt text/footer and the individual contractor/participant notification bodies in the Email inventory. Check all roles, invitation flows, invoice statuses, revision/support-file notifications, and withdrawal/draft notifications.
6. Get legal/program approval for eulas/terms.html, eulas/contractor.html, and eulas/contractor_employee.html, plus privacy/collection wording. Preserve prior agreement versions and acceptance evidence; review any related ministry-name wording as a separate approved scope, not an automatic part of this rename.
7. Obtain an old-to-new external-link/mailbox map. The contractor resources screen links to betterhomesbc.ca and esp.clearesult.ca PDF forms, brochures, consent forms, terms, requirements, and sample invoices. Frontend i18n and email bodies also contain branded links/contact addresses. Do not manufacture URLs by replacing the old name: domains, path slugs, hosted filenames, and redirects may remain intentionally unchanged. Confirm replacement document artwork/content with its external owner.
8. Review the Documentation inventory and any branding-containing runtime requirement templates separately. docs/requirement-template-sync.md points to database-driven template content; inspect deployed templates, requirement blocks, imported submission descriptions, and CMS-like program resources, which are not fully represented by a static scan. Archive historically accurate references rather than silently rewriting history.
9. Release this phase independently after the verification gates below. Record intentional legacy external URLs, historical text, technical keys, and immutable documents as an allowlist with owner and reason.
